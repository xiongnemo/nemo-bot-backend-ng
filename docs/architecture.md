# Nemo-bot-backend-ng 架构概览

`nemo-bot-backend-ng` 是下一代（Next Generation）的聊天机器人后端系统。相较于早期的硬编码指令驱动架构，它进化为以 **LLM 智能体（Agent）为核心**，融合多平台适配、动态权限管理、以及自然语言技能树的复合型架构。

## 1. 核心架构组件 (Core Components)

系统自下而上分为四个主要层级：

### 1.1 接入层 (Adapters)
位于网络最外围，负责抹平各个不同聊天平台（如 WeChat, QQ, Telegram, Discord 等）的 API 差异。
- 所有的 Adapter 会将各平台的原生事件转换为内部统一的 `Message` 对象。
- 当处理完毕后，再将统一的返回动作转化为平台原生 API 发送出去。

### 1.2 路由与执行层 (Routing & Executor)
- 当系统收到统一的 `Message` 后，`routing/ruleset.py` 会进行初步判断。
- 如果消息以特定前缀触发了传统 Plugin（插件），则直接由传统的逻辑代码接管并快速响应。
- 否则，消息将被送入核心的 **Agent Runner** 进行智能决策。

### 1.3 核心中枢：Agent 引擎 (`agent/`)
Agent 引擎是整个新架构的大脑（ReAct 架构）。
- **Agent Runner** (`runner.py`)：负责管理整个多轮大模型对话循环。
- **动态 Prompt 注入** (`prompts.py`)：每次构建对话前，动态注入宿主机环境（OS、编码）、用户身份、**权限等级（Superuser）**、以及长期记忆，确保模型时刻拥有“上下文意识”。
- **Tool Registry** (`tool_registry.py`)：工具注册表。不仅收纳了系统内置工具（如历史搜索、思考工具），还能将底层的 Python 插件包装成大模型的 function calling。最关键的是，它**在底层物理阻断了越权工具注入**，即普通用户连危险工具的名字都看不到。
- **多模型底座** (`nemollm/`)：封装了对 OpenAI, Gemini, Anthropic 等多厂商的统一调用接口，内置了序列化（Coalescing）和 fallback 回退机制。

### 1.4 数据与记忆存储 (`store/`)
底层使用 SQLite 作为热更新存储。
- **MessageStore (历史记忆)**：用于 Agent 的短期上下文回忆和跨回合衔接。
- **StateStore (长期记忆与状态)**：用于存储跨平台的账号绑定关系、用户偏好（facts）、别名以及各种不需要重启即可生效的动态配置。

## 2. 扩展能力设计

为了打破传统的扩展瓶颈，系统设计了两套独立的扩展体系：

### 2.1 传统 Python 插件 (Plugins)
位于 `plugins/` 目录。这是硬核的代码扩展，能够直接操作系统资源。
- **双模态**：一个插件既可以作为传统命令触发（供用户直接使用），也可以暴露 `_tool_description` 作为大模型使用的 Tool。
- **安全隔离**：默认情况下，任何写入或危险操作均被建议强制加上 `requires_superuser` 校验。

### 2.2 自然语言技能 (Agent Skills)
位于 `data/skills/` 目录。这是纯文本的扩展机制，详情参见 `agent_skills.md`。
- **逻辑与工具分离**：技能本身是用 Markdown 编写的工作流（SOP），大模型阅读指令后，自动编排底层的 Python Tool 去执行。
- **零成本热更**：每次调用前动态扫描，无需重启即可赋予机器人新能力。
- **沙盒写入底座**：借助专有的 `skill_manager.py` 底层工具，模型能够在防路径穿越的沙盒中安全的自我迭代。

## 3. 权限与安全哲学

1. **零信任原则**：对于非 `superuser` 的普通用户，系统在**物理层（Tool Registry）**和**逻辑层（Prompt 注入）**均拒绝暴露任何带有写权限或破坏性的操作指令。
2. **防注入与路径穿越**：任何由大模型主导的写文件操作（如 Skill 生成），绝对禁止通过 Shell 直接调用，而是必须经过具有绝对路径白名单的专用接口拦截。
3. **高危阻断验证**：对于第三方远程动态拉取的代码（如第三方 Skill 脚本），系统内置预警和暂停机制，必须经由人工 Owner 在聊天窗口授权方可落盘。
